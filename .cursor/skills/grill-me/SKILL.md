# grill-me（本仓）

源自个人 skill `grill-me`。本仓 T1–T7 及后续非琐碎改动**必须先走本 skill**，不要把它写成任务列表里的一条功能。

## 核心规则（原文）

1. 在整体计划达成共识之前，把用户往死里问
2. 顺着思路延伸，把每个决定背后的连锁反应抓出来问到底
3. 每次只能问一个问题
4. 必须附上建议答案
5. 达成共识之前，绝对不准偷偷写代码，执行任务

## 启用与期限

- 用户提出新目标、新功能、重构、脚本、文档或任何非琐碎任务时：**先读本 skill，再 Grill**
- 用户说「grill-me」「先对齐」「别急着做」时：强制启用
- **不设固定期限**：持续启用，直到用户明确说「可以松一点 / 暂停 grill-me / 关掉 grill」再手动调整
- 仅当用户已明确说「按这个做 / 达成共识了 / 开始执行」且计划已对齐时：结束本轮 Grill，再动手

## 工作流

1. **停止执行**：不写代码、不改文件、不跑会改变状态的命令、不偷偷「先做一部分」。
2. **识别缺口**：目标、范围、成功标准、约束、取舍、连锁影响（对现有流程/目录/依赖/验收的影响）。
3. **只问一个问题**：本轮回复里只能有一个待答问题；不要一次抛出清单。
4. **附上建议答案**：每个问题必须带你认为最合理的默认选项，便于用户直接确认或改口。
5. **顺着连锁反应追问**：用户每确认一点，立刻追问该决定带来的下游影响，直到关键路径闭环。
6. **防瘫痪**：追问收益递减时（关键路径已闭环、剩余多为细枝末节），列出 3–5 条「已知风险 / 未决项」，然后只问一句是否按此进入执行——不要无限问下去。
7. **共识复述**：动手前用几句话复述整体计划（目标、范围、不做的事、成功标准）；用户点头后再执行。

## 提问格式

```text
**问题：** <唯一一个问题>

**建议答案：** <可直接采纳的默认选项；必要时给 1–2 个备选并标明推荐>
```

## 逃生口

用户说「跳过 grill」「直接做」「别问了先做」时：**立即停止追问并执行**当前已理解的指令，不再为对齐而阻塞。

## 同任务不重烤

- 本轮任务的整体计划一旦达成共识并开始执行，执行中的微步骤、实现细节**不再从头 Grill**
- 仅在出现以下情况时重新启用 Grill：范围变了、目标变了、成功标准变了、或发现原计划的关键假设不成立

## 禁止

- 共识前写代码、改仓库、跑任务流水线、创建大量文件
- 一轮问多个问题
- 只提问不给建议答案
- 假装已对齐而开始动手
- 已对齐后对每个微步骤重新长问，导致无法推进

## 例外（仍须先口头确认范围极小）

- 用户给出完整、可执行的明确指令且无副作用（如「把这句话改成 X」）
- 纯只读查询（解释某段已有代码/文档，不改任何东西）

## 本仓补充（相对个人版多出来的）

对齐之后、写代码之前，若改的是产品口径：先走本仓 `design-current-state`（改现行需求/设计/测试/过程日志）。

固定约束（Grill 时当已知，不必当功能任务再问一遍）：

- 不改万象术业务逻辑
- 效果实验一次只变一个因子；156 全量不当效果结论
- 回复与文档用简体中文
- 宣称完成前走 `sdlc-self-check`
