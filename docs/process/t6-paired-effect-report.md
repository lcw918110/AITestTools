## 三、92 题唯一失败的完整定性

- **现象**：r4 断言下 2 次复跑稳定失败（`MODEL_TASK`）；
- **根因**：`deploy-anchor` 要求英文 `deploy`、`spike-anchor` 要求「错误激增」，
  而模型中文语境输出「部署时间戳」「错误率尖峰」——**语义完全正确**；
- **定性**：试题断言用词缺陷（中英混杂），非模型能力问题、非插件回归；
- **处置**：r5 放宽正则（`deploy|部署`、`error.?spike|spike|错误激增|错误率尖峰|尖峰`），
  复跑 **PASS ✅**，整库校验 319/319 全绿；
- **归因**：与插件无关，属判题器与试题的用词对齐问题。

## 四、引擎缺陷修复（随 `618f710` 落盘）

1. **`sandbox-runtime.ts`**：`wrapHostCommand` 长跑进程内周期性永挂
   （仅「真实跑题 × 长跑进程」触发，纯 wrap 循环 180 轮不可复现）
   → reset→initialize→wrap 链外加 **60s 硬超时**，死锁降级为单题
   `HARNESS` 快速失败，整批不再被拖死；
2. **`hosted-runner.ts`**：deadline 定时器 `unref()` 在事件循环无其他
   驱动句柄时被吞 → 改 **`ref()`** 显式持有，超时保证恢复严格；
3. **L2 根因开放**：sandbox-runtime 第三方包内部连接排水/状态污染，
   需上游或 node inspector 专项定位（现有兜底已把影响压到单题 60s）。
