# ADR-0013：首期隔离后端只接 sandbox-runtime

| 字段   | 值                         |
| :----- | :------------------------- |
| 状态   | **已采纳**                 |
| 日期   | 2026-10-29                 |
| 决策人 | grill-me 对齐（用户「同意」） |

## 背景

FR-12 要求真实 Agent/插件任务在目标操作系统的强制边界内执行。独立工作目录、`HOME`/`XDG` 覆盖和驱动标签都不能当作隔离证明。微软 MXC 的进程容器要求更高的 Node 版本，且 macOS 后端仍是实验状态；微虚拟机边界更硬，但引入系统服务和镜像，不适合首期。

## 决策

1. **首期只注册一个后端**：`sandbox-runtime`，实现包为 `@anthropic-ai/sandbox-runtime`。它按操作系统调用 Seatbelt、bubblewrap 或 Windows 试验隔离，不把这三种机制写成三个可互相替代的产品后端。
2. **Windows 默认拒绝真实运行**。注册状态为 `degraded`，在本机探测未通过前不得启动真实宿主。macOS 的探测证据不能继承到 Windows 或 Linux。
3. **探测失败即关闭**。真实运行前必须证明：工作区外不可写、凭据路径不可读、未允许的出站连接被拒绝、超时或取消能清理进程树。少一项就拒绝，不能靠配置、驱动标签或界面勾选放行。
4. **不进首期**：微软 MXC、Job Object 或受限令牌单独充当后端、tokimo 及其他微虚拟机。以后若引入，必须另有注册项和本机证据，不能自动降级到更弱边界。

## 后果

- 正面：三平台调用方式统一；当前机器可先验证 macOS；Windows 缺口被明确登记而不是假装已隔离。
- 负面：Windows 在完成安装和本机探测前不能跑真实宿主；sandbox-runtime 的 Windows 支持仍是试验版，系统自带 `curl`、PowerShell 和 .NET 的 HTTPS 在沙箱内可能失败。
- 不做：不改万象术业务逻辑；不把 156 全量当效果结论；不在本机没有对应操作系统时宣称该系统已验证。
