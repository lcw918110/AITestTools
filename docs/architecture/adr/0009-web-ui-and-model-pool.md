# ADR-0009：全面界面化与全局模型配置池

| 字段   | 值                   |
| :----- | :------------------- |
| 状态   | **已采纳**           |
| 日期   | 2026-10-19           |
| 决策人 | grill-me 对齐（§29） |

## 背景

本项目此前以「终端 CLI / console 脚本」为界面形态，`apps/console/` 输出终端文本/表格。但 `docs/03-界面与交互设计.md` 早已定义了一套完整的现代化 Web 界面（导航、Provider/模型页、运行详情、对比分析、安全交互等），代码侧尚未实现。

同时，评测体系需要「裁判模型」与「完成任务模型」两类模型调用，二者都需要一个统一、可维护的模型配置来源（参数、分类、基本信息、密钥引用），当前密钥硬编码在 `src/drivers/model-adapter/promptfoo.ts` 中直接读环境变量，无统一配置池。

## 决策

1. **界面形态升级为现代化 Web 界面**，不再以终端 console 为交互形态：
   - 复用现有 `src/` 领域层与 run 引擎作为后端核心，外包一层 HTTP API。
   - 前端沿用现有 `apps/console/public/` 的**原生 JS + HTML 单页**形态（无框架），按 `docs/03` 设计逐步扩展页面，覆盖录题、环境、数据集、跑批、报告、裁判、模型配置等。
   - `apps/console/` 的终端脚本（`bank.ts` / `dashboard.ts` 等）**不立即删除**，先与 Web 界面并行，逐步迁移，最终退役。
   - 数据层沿用现有文件驱动（`project.json`、`environments/`、`dataset-releases/`、`models.json`），不引入数据库。
2. **新增全局模型配置池 `models.json`**：
   - 复用领域类型 `Provider` / `ModelCatalogEntry`，扩展 `params`（参数档）、`api_key_env`（密钥引用）、`category`（主分类）、`tags`（多值标签）。
   - 密钥只存「环境变量引用名」（如 `api_key_env: "DEEPSEEK_API_KEY"`），明文密钥在本机 `.env`（gitignore），配置文件可进 git 不泄漏。
   - 使用处（环境 `recipe.host_model`、题目 `revision.model_id`、裁判模型配置点）解析模型时查 `models.json`，未命中则按使用处信息自动登记最小条目回写。
3. **裁判体系三类来源**（详见 `docs/02` §5.1）：
   - 题目对比（确定性 oracle）：必现，run 内自动跑。
   - 模型判断（LLM-as-judge）：人为触发。
   - 人工判断（human）：人为触发。

## 后果

- 正面：界面符合 `docs/03` 既定设计；模型配置统一可维护、密钥不落明文进 git；裁判三类来源语义清晰。
- 负面：需新增 Web 服务层与前端工程；console 迁移存在过渡期双轨维护成本。
- 不做：不重写 `src/` 领域层与 run 引擎；不引入数据库或微服务架构；不在界面明文录入密钥。

## 分期

- **第 0 期（已落地）**：在现有 `apps/console/` HTTP 服务上扩展——全局模型配置池 `models.json`（含 Web 界面增删改查）+ 裁判体系（三类）。
- **第 1 期（已落地）**：录题、环境管理、数据集管理界面化（见 changelog §33）。
- **第 2 期（已落地）**：跑批、报告/趋势、健康检查界面化；console 退役收尾（见 changelog §36、§38）。
