## 2. 新物理协议（cases-v1）

### 2.1 协议版本

`asset_protocol: "cases-v1"`（替代 `papers-v1`）。旧 `papers-v1` 资产进入 `docs/archive/` 与 `examples/*/legacy/`，保留供历史 run 产物 compare 读取。

### 2.2 目录结构与文件命名

```
<project>/
├── exam.json                              # 清单（cases-v1）
├── cases/                                 # Case 逻辑身份（*.case.json）
│   └── paired-task-22.case.json
├── case-revisions/                        # CaseRevision 不可变修订（*.case-revision.json）
│   ├── paired-task-22.r2.case-revision.json    # OFF 修订
│   └── paired-task-22.r3.case-revision.json    # ON 修订
├── dataset-releases/                      # DatasetRelease 冻结闭包（*.dataset-release.json）
│   └── paired-off.dataset-release.json
├── environments/                          # EnvironmentProfile（*.environment.json）
│   └── hosted-plain-v1.environment.json
├── candidates/                            # CandidateConfig（*.candidate.json）
│   ├── hosted-plain.candidate.json
│   └── hosted-plugin.candidate.json

```

## 4.1 已知缺陷：迁移字段丢失（已决策：方案 A）

阶段 4a 审查发现，迁移脚本在拆分 freeze/room 时**丢失了 runner 执行必需字段**：

| V1 字段 | 数量 | 迁移后去向 | 状态 |
| :--- | :--- | :--- | :--- |
| `freeze.model_id` | 318 | 未迁移 | ❌ 丢失 |
| `freeze.prompt_template` | 318 | 未迁移 | ❌ 丢失 |
| `freeze.channel` | 318 | 未迁移 | ❌ 丢失 |
| `freeze.tool_profile` | 318 | 未迁移 | ❌ 丢失 |
| `freeze.host_profile` | 318 | 迁移为 `candidate.model_routing`（间接） | ⚠️ 语义变化 |
| `room.host.model` | 4 | 未迁移 | ❌ 丢失 |
| `room.host.agent` | 4 | 迁移为 `candidate.agent.name` | ⚠️ 部分保留 |
| `room.host.managed_agents` | 4 | 未迁移 | ❌ 丢失 |
| `room.host.command` | 4 | 未迁移 | ❌ 丢失 |

**决策（2026-10-17）：方案 A——扩展字段，无损迁移。**

理由：
1. 方案 A 最小改动，不新建资产类型；方案 B（ModelRoutingProfile）属 Phase 4 功能目录/路由范畴，可后续细化
2. 方案 A 保留 V1 全部信息，满足深迁移「无损」要求
3. `freeze.model_id`（基准模型）与 `room.host.model`（host 默认模型）语义不同，分别归属 CandidateConfig 与 EnvironmentProfile

**方案 A 字段扩展：**

- `CandidateConfig` 增加：`model_id`（基准模型）、`prompt_template`、`channel`、`tool_profile`
- `EnvironmentProfile.recipe` 增加：`host_command`、`host_model`、`host_agent`、`managed_agents`

> 注：若明早审核认为应改方案 B（新建 ModelRoutingProfile），可在此基础上升级——方案 A 的字段扩展是无损的，方案 B 只是把 model_id/host.model 从 CandidateConfig/EnvironmentProfile 抽到独立路由资产。

已完成：

- **字段完整性修复**：`Case` 补 `pair_key`、`CaseRevision.stimulus` 补 `hosted_pass_token`、`EnvironmentProfile.recipe` 补 `host_plugin`/`durable_log_glob`（此前类型定义滞后于 schema/产物）

- **`intent.statement` 归属**：V1 `intent.statement`（题目意图）在 runner 链路 0 处消费，迁移后暂用 `Case.title` 顶替；是否需要在 CaseRevision 新增 `statement` 字段以无损保留，待确认。
